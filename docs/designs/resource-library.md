## Vision

### 10x Check

The 10x version is a guitarist's permanent practice binder: every useful video, tab, and reference they've ever touched, organized by technique, searchable by tag, auto-suggested when they start a session. Not a per-session attachment list — a growing, curated library that gets smarter over time. The session doesn't create resources; it pins them. When you start a session on barre chords, the library surfaces your Justin Guitar barre chord series automatically. When you finish, it prompts you to save any ad-hoc links you found. Over months, the library becomes a mirror of your learning history. That's not a utility feature — that's the app's memory. The guitarist's progress is embedded in what they've saved.

## Accepted Scope (added to this plan)

- **Approach C: Global resource library** — new Firestore collection `users/{uid}/resources/{id}`, reusable across sessions
- **Session pinning** — Before phase picker selects from library + adds new resources; both written to global library AND copied to session subcollection on save
- **Library browser page** — `/app/resources` route + `ResourceLibraryComponent` for browsing and managing the full library
- **Resource tags** — `tags?: string[]` field on the Resource model; tag-based filtering in library browser
- **Model telemetry fields** — `lastUsedAt?: Timestamp` and `useCount?: number` on Resource model (data accumulates now; quick-select UI ships later)
- **YouTube oEmbed preview** — when a YouTube URL is pasted, fetch title + thumbnail via `https://www.youtube.com/oembed?url={url}&format=json` (no API key required); auto-fill the label field; show thumbnail below URL input
- **Library resource delete/edit (T4)** — delete with confirm dialog + inline edit form (label + tags only; URL/type are identity fields and not editable)
- **URL deduplication in saveResources() (T6)** — before creating a new global library resource, query `users/{uid}/resources` for `url == resource.url`, limit 1. If found: reuse existing ID and call `touchResource()`. If not found: create new doc.

## Data Model

### Session phases overview

The app has three phases per session (Before → During → After). The resource picker is shown in the **Before** phase (session setup); resources are displayed read-only in **During** (timer running) and **After** (reflection). This is the source of all "Before phase" / "During phase" references throughout this document.

### Resource interface (global library)

```ts
// src/app/models/resource.ts
export interface Resource {
  id?: string;
  type: 'youtube' | 'pdf' | 'chord-sheet' | 'custom';
  // chord-sheet: URL to an online chord/tab site (e.g. Ultimate Guitar).
  // Treated identically to 'custom' in v1 but typed separately for future filtering.
  url: string;
  label: string;
  tags?: string[];      // free-form lowercase strings; see Tag UX below
  useCount?: number;
  lastUsedAt?: Timestamp;
  createdAt: Timestamp;
}
```

### SessionResource interface (session pin)

```ts
// src/app/models/session-resource.ts
export interface SessionResource {
  id?: string;
  resourceId?: string;  // FK to users/{uid}/resources/{id}
                        // undefined for newly-created resources until saveResources() resolves
  type: 'youtube' | 'pdf' | 'chord-sheet' | 'custom';
  url: string;
  label: string;
  tags?: string[];
  pinnedAt: Timestamp;  // when it was attached to this session
}
```

**`resourceId` timing note:** When a user adds a new resource via the picker (not selected from existing library), that resource is created in `users/{uid}/resources/{id}` during `saveResources()`. The component's `_pendingResources` signal holds the resource data without a `resourceId` until `saveResources()` writes the global doc and receives its new ID. `saveResources()` sets `resourceId` on the session pin at the same time it writes the subcollection doc. No caller needs to pre-populate `resourceId` for new resources.

### Firestore paths

```
users/{uid}/resources/{id}                    ← global library
users/{uid}/sessions/{sessionId}/resources/{id}  ← session pins (denormalized copy)
```

## Key Implementation Notes

### `extractYouTubeEmbedUrl()` spec

Handles these input formats and returns `https://www.youtube.com/embed/{videoId}`:
- `https://www.youtube.com/watch?v=VIDEO_ID` — extract `v` query param
- `https://youtu.be/VIDEO_ID` — first path segment
- `https://www.youtube.com/shorts/VIDEO_ID` — second path segment after `shorts`
- `https://www.youtube.com/embed/VIDEO_ID` — already embed, return as-is

Returns `null` for any URL that doesn't match these patterns. Used both by the resource-picker (type validation) and the session-resource display component (iframe src).

### YouTube oEmbed

```ts
// src/app/utils/youtube.ts
export interface YouTubeOEmbed {
  title: string;
  thumbnailUrl: string;
}

export async function fetchYouTubeOEmbed(url: string): Promise<YouTubeOEmbed | null> {
  try {
    const response = await fetch(`https://www.youtube.com/oembed?url=${encodeURIComponent(url)}&format=json`);
    if (!response.ok) return null;
    const data = await response.json();
    return { title: data.title ?? '', thumbnailUrl: data.thumbnail_url ?? '' };
  } catch {
    return null;
  }
}
```

**CORS:** `https://www.youtube.com/oembed` sets permissive CORS headers (`Access-Control-Allow-Origin: *`). The `fetch()` call works from any origin. If it fails (network error, private video), the label field stays empty and the user fills it manually.

The picker calls `fetchYouTubeOEmbed()` when the URL input loses focus (type === 'youtube'). Auto-fill `label` if the label field is empty. Show thumbnail below the URL input using an `<img>` bound to `thumbnailUrl`.

### DomSanitizer for YouTube iframes

```ts

// ...
get safeEmbedUrl(): SafeResourceUrl {
  // only call this getter inside @if (resource.type === 'youtube') — the ! is safe there
  return this.sanitizer.bypassSecurityTrustResourceUrl(
    extractYouTubeEmbedUrl(this.resource.url)!
  );
}
```

### CSP for YouTube iframes

```html
<!-- src/index.html -->
<meta http-equiv="Content-Security-Policy" content="frame-src https://www.youtube.com">
```

This project uses Firebase App Hosting (not static Firebase Hosting). The `firebase.json` has an `apphosting` block with no custom `headers` configuration. The `<meta>` tag approach is used because no server-level CSP is currently injected. If a server-level CSP header is ever added to the App Hosting backend config, the `frame-src https://www.youtube.com` directive must be included there and this meta tag can be removed (a server header takes precedence over a meta tag for the same directive).

### Memory-first pattern (Before phase)

```ts
// session.component.ts
private _pendingResources = signal<Omit<SessionResource, 'id' | 'pinnedAt'>[]>([]);
```

Resources live in component memory from Before phase through After phase. Persisted only when `onSubmit()` is called and `sessionService.create()` resolves with the session ID.

`_pendingResources` items do NOT get back-filled with `resourceId` after `saveResources()` completes — the signal is in-memory only and is not mutated after the save. This is safe because: (a) after a successful save, `onSubmit()` navigates away immediately; (b) after a failed save, the user retries the whole `saveResources()` call, which will create duplicate global library docs for new resources. This is an acceptable edge case (duplicate resources are not harmful) and is explicitly acknowledged rather than silently allowed.

### `onSubmit()` conversion to async/await

The current `session.component.ts` uses `.then()` chaining and discards `create()`'s return value. To support the resource save flow, `onSubmit()` must be converted to `async/await`:

```ts
async onSubmit() {
  this._loading.set(true);
  this._saving.set(true);
  try {
    const sessionId = await this.sessionService.create({ ... });
    if (this._pendingResources().length) {
      await this.resourceService.saveResources(sessionId, this._pendingResources());
    }
    this._saving.set(false);
    this._loading.set(false);
    this.router.navigate(['/app']);
  } catch (error) {
    console.error('Error saving session:', error);
    this._saving.set(false);
    this._loading.set(false);
    // Surface error via PrimeNG p-toast — do not navigate; pending resources are still in memory.
    // Use MessageService: { severity: 'error', summary: 'Save failed', detail: 'Could not save session. Please try again.', sticky: true }
    // sticky: true prevents auto-dismiss so the user doesn't miss it on slow connections.
  }
}
```

**Important:** `_loading`/`_saving` are set to `true` at the start. The submit button in the After phase template must disable while `saving()` is true to prevent double-submit. Verify the template already binds `[disabled]="saving()"` on the submit button — if not, add it.

### §T6 URL Deduplication

**Implementation in `saveResources()`:**
```ts
// For each resource where resourceId is undefined (new resource):
const q = query(
  collection(db, `users/${uid}/resources`),
  where('url', '==', resource.url),
  limit(1)
);
const existing = await getDocs(q);
let globalResourceId: string;
if (!existing.empty) {
  globalResourceId = existing.docs[0].id;
  await this.touchResource(globalResourceId);
} else {
  const ref = await addDoc(collection(db, `users/${uid}/resources`).withConverter(resourceConverter), {
    type: resource.type, url: resource.url, label: resource.label,
    tags: resource.tags ?? [], createdAt: serverTimestamp(), useCount: 0
  });
  globalResourceId = ref.id;
}
// Then write the session pin using globalResourceId...
```

**Index note:** `where('url', '==', ...)` is a single-field equality filter. Firestore automatically creates single-field indexes. No explicit entry in `firestore.indexes.json` is required.

## Reviewer Concerns

*(Carry-forward from spec review — address before implementation)*

1. **[Feasibility] Dual-write orphan (global write succeeds, subcollection write fails)** — `saveResources()` writes each resource to `users/{uid}/resources/{id}` first, then to the session subcollection. If the subcollection write fails after the global write succeeds, the library has a resource that is not attached to the session. Orphaned library resources are not harmful (they appear in the library browser and can be pinned to future sessions), but this must be acknowledged rather than silently implied. No mitigation required in v1.

2. **[Feasibility] Reverse failure mode (session saves, subcollection write fails)** — if `sessionService.create()` succeeds but `saveResources()` fails, the session exists but has no resources attached. The current error handling (inline error, no navigation) means the user can retry — the pending resources are still in component memory. No further mitigation is required, but a tab-close at this moment is an unrecoverable data loss. Defer retry/recovery to TODOS.md.

3. **[Feasibility] CORS on oEmbed fetch** — `fetch()` to `https://www.youtube.com/oembed` from a Firebase-hosted app should succeed (YouTube sets permissive CORS on that endpoint). Fallback: if the fetch fails, label field stays empty and the user fills it manually. No action required.

4. **[Consistency] `/app/resources` path deviates from camelCase convention** — all existing `/app/*` child routes use camelCase (`newSession`, `sessionDetail`, `newSong`, `songDetail`). The library browser route `resources` is lowercase. The spec intentionally uses `resources` (it is a valid, URL-friendly path), but document the deviation when adding the route entry in `routes.ts`.

5. **[Consistency] Legacy `Session` interface in `converters.ts`** — `converters.ts` still declares `Session` inline (legacy). When adding `resourceConverter` and `sessionResourceConverter`, import `Resource` and `SessionResource` from their model files rather than following the legacy pattern. Do not modify the existing `Session` inline declaration.

6. **[Completeness] `app-shell.component.ts` path** — RESOLVED: verified at `src/app/shells/app-shell.component.ts`. The `items` signal uses `routerLink: ['resources']` format. No `routerLinkActive` needed; existing nav items don't use it.

## Error & Rescue Registry

| METHOD/CODEPATH | WHAT CAN GO WRONG | EXCEPTION CLASS |
|---|---|---|
| `ResourceService#saveResources` | Firestore offline | `FirebaseError` (network-request-failed) |
| `ResourceService#saveResources` | Auth expired mid-save | `FirebaseError` (permission-denied) |
| `ResourceService#saveResources` | Global write OK, pin write fails | `FirebaseError` (partial — orphaned library resource) |
| `ResourceService#saveResources` URL dedup | Query fails (offline) | `FirebaseError` |
| `fetchYouTubeOEmbed` | Network unavailable | `TypeError` (failed to fetch) |
| `fetchYouTubeOEmbed` | YouTube 4xx/5xx | `Response.ok` = false |
| `fetchYouTubeOEmbed` | Malformed JSON from YouTube | `SyntaxError` |
| `extractYouTubeEmbedUrl` | Non-YouTube URL | returns `null` (not thrown) |
| `DomSanitizer#bypassSecurityTrustResourceUrl` | Called outside `@if (type === 'youtube')` guard | `TypeError` (null dereference) |
| `ResourceService#getResources` | Firestore read fails | `FirebaseError` |
| `new URL(input)` in picker | Invalid URL string | `TypeError` |
| `ResourceService#deleteResource` | Permission denied | `FirebaseError` |
| `ResourceService#updateResource` | Permission denied | `FirebaseError` |

| EXCEPTION CLASS | RESCUED? | RESCUE ACTION | USER SEES |
|---|---|---|---|
| `FirebaseError` (saveResources) | Y | `catch` in `onSubmit()` | Inline error, no navigation |
| `TypeError`/network (fetchOEmbed) | Y | `try/catch` returns `null` | Empty label, manual fill |
| `SyntaxError` (JSON in oEmbed) | Y | `try/catch` returns `null` | Empty label, manual fill |
| `Response.ok` false (oEmbed) | Y | Early return `null` | Empty label, manual fill |
| `TypeError` (new URL validation) | Y | `try/catch` disables Add button | Add button stays disabled |
| `TypeError` (null embed URL) | Y | `@if (type === 'youtube')` guard | No crash (guard prevents reach) |
| `FirebaseError` (getResources) | N ← KNOWN GAP | — | Picker library list empty (silent) |
| `FirebaseError` (deleteResource) | N ← KNOWN GAP | — | Delete silently fails |
| `FirebaseError` (updateResource) | N ← KNOWN GAP | — | Edit silently fails |

**Note on KNOWN GAPS:** For a single-user personal app, silent failures on `getResources/deleteResource/updateResource` are acceptable in v1. The user can reload to recover. Inline error handling for these is a P3 follow-up.
